# DaUaGateway v2 — универсальный шлюз OPC DA → OPC UA

Plug-and-play: шлюз сам находит DA-серверы на компьютере, сам читает их теги и сам публикует их по OPC UA.

## Что нового по сравнению с v1

| | v1 | v2 |
|---|---|---|
| DA-серверы | один, ProgID вручную | **все найденные автоматически** + из конфига |
| Теги | список вручную | **автообзор всего дерева** + маски include/exclude + ручной список |
| Структура в UA | плоская `DA/<тег>` | **дерево как в DA**: `Servers/<сервер>/<папки>/<тег>` |
| Типы данных | BaseDataType | **точный тип из DA** (Int32, Double, …) |
| Изменения в DA | нужен перезапуск | **пересборка на лету** (новые теги добавляются, удалённые убираются) |
| «Входящие» | — | **кинул CSV в папку — шлюз применил** |
| Запись UA → DA | — | по флагу `allowWrite` |
| Запуск | консоль | консоль **или служба Windows** с автоперезапуском |
| Логи | консоль | файлы `logs/`, ротация, контроль памяти раз в час |
| Лицензия | — | точка подключения `Licensing/LicenseHook.cs` (для заказчика) |

## Адресное пространство UA

```
Objects/
  Gateway/                 Version, StartTime, ModelVersion, SourceCount
  Servers/
    Matrikon.OPC.Simulation.1/
      _Status              "Подключено, тегов: 42"
      _Connected           true/false
      Random/
        Int4               ns=<urn:DaUaGateway:tags>;s=Matrikon.OPC.Simulation.1|Random.Int4
        Real8
      ...
```

- **NodeId тега** = `<источник>|<ItemID из DA>` — стабилен между перезапусками.
- Для удалённого DA-сервера источник называется `host/ProgID`.
- **ModelVersion** растёт при каждом изменении дерева: клиент (дашборд) подписывается на него
  и перечитывает дерево, когда появляется новый сервер или теги.
- В атрибуте Description каждого тега — исходный ItemID из DA.

> ⚠️ По сравнению с v1 изменились NodeId (было `s=Random.Int4`, стало `s=Matrikon.OPC.Simulation.1|Random.Int4`).

## Окно-пульт (v2.5)

Двойной клик по `DaUaGateway.exe` открывает небольшое окно (без чёрной консоли):
состояние, адрес для SCADA, DA-серверы, кнопки **Запустить / Остановить**, «Конфигуратор», «Журнал».
Окно сворачивается в **трей** (правый нижний угол); конвертер при этом продолжает работать.
Двойной клик по значку — открыть окно, правая кнопка — меню (Конфигуратор, журналы, Выход).
Галочка «Запускать конвертер сразу при открытии» — `data\panel.json`.
Если конвертер установлен службой — окно показывает «Работает как служба Windows».
Старый режим с консолью: `DaUaGateway.exe --console`.

## Конфигуратор 2.3 — как UaExpert

`Configurator\DaUaGateway.Configurator.exe` (подпапка конвертера, со своими библиотеками):

| Панель | Что показывает |
|---|---|
| DA-СЕРВЕРЫ (слева вверху) | DA-серверы компьютера и что выбрано у каждого |
| ДЕРЕВО ТЕГОВ DA (слева внизу) | галочки на тегах и папках + «Переводить ВСЕ теги автоматически» |
| ПЕРЕВЕДЁННЫЕ ТЕГИ (центр) | как Data Access View: NodeId, путь, значение, тип, время, статус — **живые значения из OPC UA, с выхода конвертера** |
| АТРИБУТЫ (справа) | тег в DA и его NodeId в UA, тип, права в DA и в UA, выбран ли и переводится ли |
| ЖУРНАЛ (внизу) | действия Конфигуратора, события OPC UA и журнал самого конвертера |

Индикатор вверху справа: конвертер работает / не запущен / **работает из другой папки** (тогда выбор до него не дойдёт).
Предупреждение, если Конфигуратор запущен из архива. Сертификат Конфигуратора сам добавляется в доверенные у конвертера.

## Выбор тегов: Конфигуратор (v2.2)

По умолчанию конвертер **находит DA-серверы сам, но ничего не переводит**, пока разработчик не выберет теги
в программе **DaUaGateway.Configurator.exe** (лежит в папке конвертера):

- слева — DA-серверы компьютера, справа — дерево тегов выбранного сервера;
- галочки на тегах и папках (папка = все теги внутри, включая новые);
- галочка **«Переводить ВСЕ теги этого сервера автоматически»**;
- внизу — значение, тип и права выбранного тега и его будущий адрес в UA;
- **«Применить»** — выбор сохраняется в `data\selection.json`, конвертер (консоль или служба)
  подхватывает его за ~2 секунды, без перезапуска и без разрыва связи со SCADA;
- экспорт / импорт выбора в CSV.

Выбор из Конфигуратора важнее настроек `gateway.json`. Если файла выбора нет — действует `gateway.json`
(`defaults.mode`: `manual` — ничего не переводить, `auto` — всё).

## Что переведено из DA в UA — показать в терминале (v2.1)

**Сводка** — в консоли шлюза через 20 с после старта и дальше раз в 10 минут:
```
┌──────────── DA → OPC UA: сводка ────────────
│ Schneider-Aut.OFS.2                        ✓ переведён   тегов: 3825
│ SchneiderElectric.SCADA.OpcDaServer.1      ✕ нет связи   (Server execution failed)
│ UA-сервер для SCADA: opc.tcp://ИМЯ-ПК:4840/DaUaGateway
└──────────────────────────────────────────────
```

**Команда `--list`** — работает в любой момент, в том числе когда шлюз запущен службой:
```
DaUaGateway.exe --list              сводка + первые 20 тегов каждого DA-сервера
DaUaGateway.exe --list all          все теги
DaUaGateway.exe --list "Motor*"     теги по маске
```
Каждая строка: `тег DA  →  NodeId в UA  (тип)`.

**Файлы для SCADA-интегратора:** `data\tag-map\<DA-сервер>.csv` (открывается в Excel):
`DA_ItemID; UA_NodeId; UA_Путь; Тип; Статус` — полное соответствие тегов DA узлам UA.

Также в 2.1: время выбирается для каждого тега отдельно (timestampSource=auto),
повторяющиеся ошибки связи не засоряют лог, русский текст в консоли на английской Windows.

## Настройка — gateway.json

```jsonc
"discovery": {
  "enabled": true,              // автопоиск DA-серверов
  "hosts": ["localhost"],       // где искать (удалённые хосты — через DCOM, см. ниже)
  "scanIntervalSec": 30,        // как часто искать новые серверы
  "rebrowseIntervalSec": 300,   // как часто пересобирать список тегов
  "excludeProgIds": []          // какие серверы игнорировать (маски)
},
"defaults": {                   // для всех серверов, найденных автопоиском
  "mode": "auto",               // auto — всё дерево, manual — только список tags
  "include": ["*"], "exclude": [],
  "allowWrite": false,          // разрешить запись UA → DA
  "maxTags": 20000,
  "timestampSource": "auto"     // da | gateway | auto (см. ниже)
},
"servers": [                    // необязательные правила для конкретных серверов
  { "progId": "Vendor.Server.1", "mode": "manual", "tags": ["Line1.Temp"] },
  { "progId": "Unwanted.Server.1", "enabled": false }
]
```

### Метка времени (timestampSource)

- `da` — время из DA-сервера как есть.
- `gateway` — время, когда шлюз получил значение.
- `auto` (по умолчанию) — время из DA; если DA-сервер присылает **новое значение со старым временем**
  (так делает, например, Matrikon Simulation), шлюз пишет предупреждение в лог и для этого
  источника переходит на время шлюза.

## Папка «Входящие» (inbox)

Положите в `inbox/` файл `.csv` или `.txt` (разделитель `;` или TAB). Excel: «Сохранить как → CSV (разделители — точки с запятой)».

```
ProgId;ItemId                          ← заголовок (необязателен)
Matrikon.OPC.Simulation.1;Random.UInt4 ← добавить тег
PLC-2;Vendor.Server.1;Line2.Speed      ← тег удалённого сервера (Host;ProgId;ItemId)
Matrikon.OPC.Simulation.1;!Bucket Brigade.*   ← исключить (можно маску)
```

Через несколько секунд файл применяется и переносится в `inbox/processed/`
(файл без корректных строк — в `inbox/error/`, ошибки — в `.log` рядом).
Если в файле указан сервер, которого шлюз ещё не знает, — шлюз сам к нему подключится.
Пример: `examples/tags-example.csv`.

## Запуск

**Разработка / тест:**
```
dotnet build
dotnet run
```

**Служба Windows (прод):**
```powershell
dotnet build -c Release
cd bin\Release\net48\scripts
.\install-service.ps1          # от имени администратора
```
Служба стартует автоматически с Windows и перезапускается при сбое.
Удаление: `.\uninstall-service.ps1`. Логи: `bin\Release\net48\logs\`.

> Служба работает от LocalSystem. Если конкретный DA-сервер не пускает LocalSystem
> (зависит от настроек DCOM сервера), укажите учётную запись в свойствах службы → «Вход в систему».

## Удалённые DA-серверы

Добавление хоста в `discovery.hosts` работает через **DCOM** (сложная настройка, см. v1).
Рекомендуемая схема продукта — **ставить шлюз на каждый компьютер с DA-сервером**,
а по сети ходить только по OPC UA.

## Тестирование v2 на стенде с Matrikon

1. `dotnet run` → в логе «Новый источник (конфиг): Matrikon.OPC.Simulation.1», затем «Теги: всего N, добавлено N».
2. UaExpert → `Objects/Servers/Matrikon.OPC.Simulation.1/…` — дерево как в Matrikon, типы Int32/Double/…
3. Закрыть Matrikon → все теги `BadNotConnected`, `_Connected = false`; открыть → восстановление.
4. Скопировать `examples/tags-example.csv` в `inbox/` → через ~5 с в логе «Входящие: файл применён»,
   теги `Bucket Brigade` исчезают, `ModelVersion` увеличивается.
5. Установить службу, перезагрузить компьютер → шлюз поднялся сам.
6. Прогон на ночь: в логе раз в час строка «Память: … МБ» — не должна расти.
